# セーブと再開

セーブデータは1つだけです。タイトル画面の CONTINUE で、そこから再開します。

## いつセーブするか

セーブはすべて自動です。手動でセーブする方法はありません（ロードしてやり直すことができないので、倒れたらセーブを消す仕様と合わせて、生存日数などの記録を公平に保てます）。残すべき変化が起きたときだけ、主人公の動きが落ち着いた瞬間を選んでセーブし、短い間に何度もセーブしないようにしています。前のセーブは上書きされます。

| きっかけ | セーブするタイミング |
|---|---|
| アイテムを得た・使った（拾う、揺すって落ちた物、取ったツル・樹皮・葉っぱ、水を汲む、食べる・飲む、突いた・釣った獲物、焚き火の料理ができた） | 次の落ち着いた瞬間 |
| 島を変えた（木を切る・叩く、掘る、火をつける、ハシゴ・丸太橋・水車・木工旋盤を据える、縄張りの杭を打つ、水車小屋の段階を建てる、リアカーを置く・また引く） | 次の落ち着いた瞬間 |
| 一度きりの出来事を見た（水車小屋の予定地、川の狭い所） | 次の落ち着いた瞬間 |
| バッグを閉じた（中で作った・並べ替えた・地面に置いた・装備を変えた・レシピの並び順を変えたなど、持ち物が変わっていれば） | 閉じた後の落ち着いた瞬間（間をあけずに） |
| 移動した | 立ち止まって1秒たったとき（`STILL_FRAMES`） |
| 眠っている間 | ゲーム内2時間ごと（`SLEEP_SAVE_MINUTES`。実時間で約1秒ごと） |
| 目覚めた | すぐ |
| ページを離れる（タブを隠す・閉じる） | すぐ（セーブしていない変化があれば） |

- **落ち着いた瞬間**: 主人公が待機中で（歩く・振る・食べるなどの途中ではない）、ヒットストップの最中でもないとき。バッグを開いているあいだは世界が止まっているので、閉じてからセーブします。動作の途中はセーブしないので（「保存しないもの」）、食べるためにバッグから出した物も、食べ終わってからセーブします。
- **間隔**: 自動のセーブどうしは最低3秒あけます（`MIN_GAP_FRAMES`）。そのあいだに起きた変化は、まとめて1回でセーブします。目覚めたとき、眠っている間、バッグを閉じたとき、ページを離れるときは待ちません。
- **保険**: セーブしていない変化が実時間で60秒残ったら（`FALLBACK_FRAMES`）、次の落ち着いた瞬間にセーブします。
- それだけではセーブしないもの: 時刻、体力・満腹度・水分・疲れ、蟹や魚の動き、松明の燃え具合、日付が変わって打ち上がる貝殻や流木。次にセーブするときに一緒に入ります。
- 倒れたあとはセーブしません（セーブは消えます）。タイトル画面でもセーブしません。
- **セーブした印**: セーブすると、画面右上の時計の下に、ノートのアイコン（8×8、白）が1秒ほど出ます。ペンが2行を書き込み、書き終えたページをめくって白紙に戻るまでを1回だけ動かして消えます（10コマ×6フレーム。`SAVED_SIGN_HOLD`）。眠っている間は1秒ごとにセーブするので、続けて動きます。
- 書き込みはページ側が、ゲームを止めないよう空いた時間に行います。書き込む前に次のセーブが来たら、最新のものだけを書きます。セーブを消すとき（倒れたとき）と、ページを離れるときはその場で書きます。

### コードの構成

- いつセーブするかは `wasm/src/game/autosave.rs` の `AutoSave` が1か所で決めます。ゲームは起きたこと（`Cue`）を知らせ、毎フレーム主人公が落ち着いているかを渡し、`AutoSave` が今セーブするかを答えます。セーブのきっかけを足すときは、ここに知らせを足します。
- 主人公の行動（`Deed`）がセーブにとって何を意味するかは `autosave::cue_of` に書いてあります。行動を足すと、ここで決めるまでコンパイルが通りません。
- ページ側は `src/game/saveWriter.ts` が書き込みをまとめ、`src/game/wasmCore.ts` がページを離れるとき（`visibilitychange`・`pagehide`）に `flush_save` でその場でセーブさせます。

## 倒れたとき

体力が0になって倒れると、セーブデータを消します。やり直しは最初からです（生存日数などの記録を公平に保つため）。島から脱出したとき（[狼煙](README.md#狼煙)で救助されたとき）も同じく消します。

## タイトル画面

- セーブデータがあると、START の下に CONTINUE が出て、カーソルは CONTINUE に合っています。
- セーブデータがあるのに START を選ぶと、「START A NEW GAME? / THE SAVED GAME WILL BE LOST.」と聞きます（YES / NO。最初は NO）。
  - YES で新しいゲームを始めます。セーブデータは、新しいゲームで最初にセーブしたときに上書きされます（それまでに倒れた場合は消えます）。
  - NO か B でメニューに戻ります。
- 読めないセーブデータ（壊れている、ゲームより新しいバージョンのもの）は CONTINUE に出しません。データは残し、START を選んだときは同じように確認します。

## 保存するもの

島は設計図と固定のシードから毎回同じに作れるので、島全体は保存しません。変わったところだけを保存します。

| 分類 | 保存するもの |
|---|---|
| 時間 | 日付と時刻 |
| 主人公 | 体力・満腹度・水分・疲れ（画面に出ない値と、減り具合の端数も）、体調の悪さとその残り時間（`ailments`。お腹を壊しているなら `UpsetStomach` と残りの分数）、生水を飲んだことがあるか（`drunk_raw_water`。最初の1回は必ず大丈夫なので）、位置と向き（水車小屋の中にいるときは、中の部屋の位置。部屋はマップの島の南の行にあるので、位置だけで中か外かがわかる）、服装（プリセットの番号）、水車小屋の予定地に初めて来たときの出来事を見たか（`castaway` の `mill_noticed`。一度きりなので）、川の狭い所に初めて来たときの出来事を見たか（`castaway` の `bridge_noticed`） |
| 持ち物 | バッグの中身と並び・バッグの段数、装備（`gear`: 手の `hand`・背中の `back`・腰の `waist` と、道具帯の鉤に提げた道具 `belt`（鉤ごとに道具の名前か `null`）。提げた道具はバッグには入っていない）、リアカーの荷台の中身（`inventory` の `cart`。作っていなければ `null`。荷台の幅 `width` も入る。バッグの幅は決まっているので書かない）、松明に火をつけた時刻、思いついたレシピ・まだ開いていないレシピ・作り方が2つ以上ある物を前に作った作り方・レシピごとに物を作った回数（`recipes` の `made`。レシピの名前と回数の組で、一度も作っていないレシピは入れない。例: `{"StoneKnife": 3}`。脱出の記録の「作ったアイテムの種類」を数え、[作れる数](README.md#作れる数)の制限にも使う）（どれもレシピの名前で保存。物を作る最初のレシピは作る物と同じ名前）、CRAFT の一覧の並び順（`recipes` の `sort`。`AToZ`・`CanMake`・`New`・`NotMade` のどれか）、一度でもバッグに入ったことのあるアイテムの種類（`inventory` の `had`。アイテムの名前で保存。レシピを思いつく条件に使う） |
| 島の変化 | 作り直した島と比べて置物が違うマス（切り株、切った竹、取ったツル、拾った貝殻、割った流木・打ち上がった流木、立てかけたハシゴ、かけた丸太橋、据えた水車、据えた木工旋盤、打った縄張りの杭（`Marking`。隅の杭か `stake` と、縄の向き `ropes`）、普請台（`SiteBench`。屋根と戸ができると、小屋の中の部屋の作業台のマスに移る）、水車小屋の土台（`Foundation`。礎石のマスは `true`）と骨組み（`Framed`。柱の立つマスは `true`）と壁（`MillWall`）と戸（`MillDoor`。どこまで開いているかは入れない）、据えた狼煙台（`SignalFire`。燃えているかも入る）、今日掘った粘土の露出（`ClayBed` の `dug`）など）、作り直した島と数が違う木の椰子の実・松ぼっくり（どちらも `fruit`）と樹皮、木を叩いた回数・揺すった回数・茂みの葉を取った日 |
| 島にあるもの | リアカー（`island` の `cart`。作っていなければ `null`。真ん中の位置 `at`、引いているか `pulled`、棒の向き `poles`）、地面に落ちているアイテム（落ちている途中のものは着地点に）、焚き火（場所と火をつけた時刻）、狼煙台（`signal_fires`。マスと、燃えている間は火を付けた時刻 `lit_at`）、最後に狼煙に火を付けた日（`signal_day`。その日の救助の見込みはもう使った）と救助が来る時刻（`rescue_at`。煙が見つかることに決まったときだけ。見つからないときは `null`）、生きている蟹の位置、魚の位置、魚の補充予定、貝殻の打ち上げの管理、区画ごとの眠り始めた時刻、水車小屋の進み具合（`island` の `mill`。建てた段階の数 `built` と、次の段階に敷地へ納めた数 `delivered`（段階の材料の順に））|

保存しないもの: 火の粉や水しぶき、カモメ、投げている釣り糸（再開すると竿を上げた状態）、揺れている木、動作の途中（再開すると立った状態）、蟹や魚の動きの途中の向きや目的地、水車小屋の戸がどこまで開いているか（再開すると閉まっている）、水車小屋の屋根を作っている途中であること（作業の途中なのでセーブしない）、水車小屋の戸を通って画面が切り替わっている途中であること（再開すると、切り替わる前か後の位置に立っている）。

## 形式とバージョン

- ブラウザの localStorage に、`castaway-island.save` という名前で JSON の文字列として1件だけ置きます。書き込みはページ側（`src/game/wasmCore.ts`）が行い、中身は Rust 側（`wasm/src/game/save.rs`）が作ります。
  - ホーム画面にインストールしたアプリ（[操作の手段](README.md#操作の手段)）も同じ置き場所を使いますが、ブラウザのタブと共有するかは端末しだいです（iPhone では別になります）。
- JSON の先頭に `version`（セーブデータの形式の番号）が入ります。今は **7** です。
- 読み込むときは、まず `version` を見ます。古ければ変換（マイグレーション）を順に当てて今の形にしてから読みます。ゲームより新しい番号のもの、読めないものは読み込みません。

### 形式を変えるとき

保存するものを足す・消す・名前を変える・意味を変えるときは、次の3つを同じ変更の中で行います。

1. `wasm/src/game/save.rs` の `SAVE_VERSION` を1つ上げる。
2. 同じファイルの `MIGRATIONS` に、1つ前の版の JSON を新しい版に書き換える関数を1つ足す（足した項目に既定値を入れる、名前を付け替える、など）。
3. このページの「保存するもの」と、下の「版の一覧」を更新する。
4. 新しい版のセーブの見本を `wasm/src/game/save_samples/v<新しい版>.json` に置いて `save.rs` のテストの `SAMPLES` に足し、足した変換がすることを確かめるテストを書く。見本はスナップショットツールの `SNAP_SAVE_OUT` で書き出せる。変換を確かめたい物（ずらす置物など）は、1つ前の版の見本に手で書き足してよい。見本は版1から今の版まで全部そろえておく（足りないとテストが失敗する）。

- アイテムの種類やレシピは名前（`StoneAxe` など）で保存しています。アイテムやレシピを足すだけなら版を上げなくて済みますが、名前を変えたり消したりするときは版を上げて変換を足します。
- 島の設計図を描き変えると、作り直した島と比べた差分の意味が変わります。すでにあるマスの形を変えるときは、変換で差分を直すか、古いセーブを読めないものとして扱うかを決めます。

### 版の一覧

| 版 | 内容 |
|---|---|
| 1 | リリース前に版を数え直した最初の版 |
| 2 | 装備に腰（`gear` の `waist`）と道具帯の鉤（`belt`）、リアカー（`island` の `cart`）とその荷台の中身（`inventory` の `cart`）を足した。版1のセーブは、腰に何も締めず鉤も空（`waist: null`、`belt: [null, null]`）、リアカーを作っていない（どちらの `cart` も `null`）として読む |
| 3 | 狼煙台（`island` の `signal_fires`）と、最後に狼煙に火を付けた日（`signal_day`）・救助が来る時刻（`rescue_at`）、一度でも物を作ったことのあるレシピ（`inventory` の `recipes` の `made`）を足した。版2のセーブは、狼煙台を据えておらず火も付けていない（`signal_fires: []`、どちらも `null`）、まだ何も作っていない（`made: []`）として読む |
| 4 | CRAFT の一覧の並び順（`inventory` の `recipes` の `sort`）を足した。版3のセーブは、アルファベット順（`AToZ`）として読む |
| 5 | 水車小屋の進み具合（`island` の `mill`）を足した。版4のセーブは、まだ何も建てておらず敷地に何も納めていない（`built: 0`、`delivered: []`）として読む |
| 6 | 一度でもバッグに入ったことのあるアイテムの種類（`inventory` の `had`）を足した。レシピを思いつく条件が「材料を同時に持つ」から「材料をどれも一度は手に入れたことがある」に変わったため。版5のセーブは、手に入れたことのある物を正確には残していないので、今の持ち物（バッグ・装備・道具帯・リアカーの荷台）、思いついたレシピの材料、作ったことのあるレシピで作る物、水車小屋の敷地に納めた物の種類を、手に入れたことがあるとして読む |
| 7 | `recipes` の `made` を、作ったことのあるレシピの名前の一覧から、レシピごとに作った回数（名前と回数の組）に変えた。作れる数に「何個まで」の制限（スポーク車輪は2個まで）を付けたため。版6のセーブは、一覧にあるレシピをそれぞれ1回作ったとして読む。ただし、リアカーを持っている（`inventory` の `cart` が `null` でない）か、リアカーを作ったことがあるときは、スポーク車輪をリアカーに使った数（2）だけ作ったとして読む（版3より前のセーブは作ったことを記録していないため、リアカーを持っていても `made` にないことがある） |

- リリース前は遊んでいる人がいないので、それまでに上げた版と変換はすべて消し、その時点の形を版1として数え直しています（消した変換と古い版の見本は git の履歴にあります）。これまでに2回数え直しました（版15から、川の狭い所の出来事を足した版2から）。数え直す前の版のセーブは、ゲームより新しい版として読み込まず、CONTINUE に出ません。中身は版1と同じ形なので、`version` を 1 に書き換えれば読めます。
- リリースした後は数え直しません。遊んでいる人のセーブが読めなくなるためです。形式を変えるときは、上の「形式を変えるとき」のとおり版を上げて変換を足します。

## 確認ツール

スナップショットツールで、セーブと再開を確かめられます（使い方はリポジトリ直下の [README](../README.md)）。

- `SNAP_RELOAD=1`: 最後にセーブし、そのセーブから再開したゲームを描きます。再開したゲームをもう一度セーブして、同じ中身になるかも調べます。
- `SNAP_SAVE_OUT=path`: セーブデータをファイルに書き出します。
- `SNAP_SAVE_IN=path`: そのセーブデータがある状態で始めます（`SNAP_TITLE=1` と合わせるとタイトルに CONTINUE が出る）。
- 実行中にセーブや削除が起きると、「saved game: saved / erased」と出力します（自動のセーブも出ます）。
